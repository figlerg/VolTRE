# Delta-Sigma modulator case study (paper Fig. 8) - Simulink side

This folder holds the MATLAB/Simulink half of the Delta-Sigma falsification case
study. VolTRE produces the timed inputs, Simulink runs the modulator model on
them, and the resulting trajectories are what Fig. 8 falsifies against.

## What belongs here (Thao to add)

- the Simulink model (`.slx`) of the Delta-Sigma modulator
- any MATLAB glue that loads an input file, runs the model, and writes/plots the
  falsification result
- a short note on the parameters used (sampling rate Fs, the mu/kappa scaling)
  so the run is reproducible from the committed inputs

## Inputs (already generated by VolTRE)

The model consumes ASCII input files, one `<date> <symbol>` line per event,
produced by sampling the TRE specs. They live next to this folder:

- `../08_nicolas_spec.tre_10/`, `../08_nicolas_spec.tre_15/`
- `../08b_nicolas_spec_fat_thin.tre_10/`, `../08b_nicolas_spec_fat_thin.tre_15/`
- `../08c_thao_spec.tre_10/`

Each folder has `s_000`, `s_001`, ... (100 sampled trajectories per spec). The
specs themselves are `../08a_nicolas_spec_5_inf.tre`,
`../08b_nicolas_spec_fat_thin.tre`, `../08c_thao_spec.tre`; the sampler is
`../08s_delta_sigma_nicolas.py`.

## Scope in the artifact

The Simulink run needs a licensed MATLAB/Simulink toolchain, so it is not
re-runnable inside the artifact. The artifact ships the model and the VolTRE
inputs for transparency; STATUS.md lists Fig. 8 as "data provided, not
re-runnable".
